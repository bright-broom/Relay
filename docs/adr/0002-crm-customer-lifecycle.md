# ADR 0002：顧客の変更を版・監査・再送記録と一体で扱う

2026-09-17 / ローカル実装に採用。本番マイグレーションは未実施。

登録済みの顧客を編集できるようにすると、別画面からの更新や通信切断後の再送で、後続の変更を上書きする可能性がある。アーカイブも同じ顧客の変更として扱う必要がある。

PATCH に edit / archive / restore と文字列の version を必須化する。現在の権限をロック・確認し、要求キーのロック、顧客行のロック、版の照合、変更、監査、再送記録を同じトランザクションで実行する。通常一覧から外すアーカイブと復元を提供し、物理削除は許可しない。RLS の更新許可は編集者・業務管理者に限定し、変更できる列を絞る。

再送は元の操作を再実行せず、適用済みの版と現在の顧客を返す。例えばアーカイブ後に復元された場合、古いアーカイブ要求を再送しても復元を取り消さない。元の版の全文保存を避け、監査には変更項目と前後の版だけを残す。

競合時は 409 を返す。入力を保持して最新の保存内容を別に表示し、利用者が確認してから編集し直す。自動マージや入力内容の自動再適用は行わない。失敗した監査・再送保存を成功扱いにしない。

今回の対象は顧客名・種類とアーカイブ状態。案件・タスクの実装時には未完了業務のアーカイブ制約を同じ処理に統合する。実装範囲・移行・検証・撤退手順は [CRM_IMPLEMENTATION.md](../CRM_IMPLEMENTATION.md) を正本とする。
