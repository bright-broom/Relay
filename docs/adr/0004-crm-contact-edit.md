# ADR 0004: 共有する連絡先の情報を版付きで編集する

2026-09-17 / 実装済み・本番未適用

## 課題と範囲

登録後の氏名・メール・電話を訂正できないため、情報が古くなった場合に同じ人を再登録する必要があった。ADR 0003 で後続とした情報編集を追加する。顧客別の関係と主連絡先の切り替えは、別の状態遷移として残す。

## 決定

- contacts の既存 version を文字列のまま API へ公開し、同じ版からの同時編集は片方だけを受理する。JavaScript の数値精度に依存しない。
- 所属・顧客・連絡先の関連を毎回確認する。氏名・メール・電話・更新日時・版の列権限だけを 006 で追加し、関連先・主連絡先・アーカイブ・削除の権限は追加しない。
- 認可行、要求キー、顧客、連絡先の順でロックする。別顧客から共有連絡先へ到達しても、連絡先行と version で競合を検出する。
- 連絡先、監査、再送記録を同じトランザクションで確定する。監査は変更項目名と版を記録し、氏名・メール・電話を複製しない。
- アーカイブ済み顧客からの新規編集は拒否する。既に確定した編集の再送は最新情報を返し、後続変更を上書きしない。
- 画面は競合した下書きを保持し、最新情報と並べる。最新情報の採用には明示操作を要求し、取得失敗でも下書きを消さない。

## 共有と互換性

連絡先の情報は同じ所属内で共有する。別の有効な顧客から更新すると、アーカイブ済みの顧客が参照する同じ連絡先にも反映する。顧客アーカイブは履歴スナップショットではない。関係テーブルを変更する将来の API も、顧客・連絡先のロック順序と共有の影響範囲を再検証する。

API の版フィールドは追加変更。006 は既存データを保持する権限・ポリシー追加であり、旧コードの登録・参照を壊さない。未適用で編集を許可しないことと、適用後の既存データを検証する。

PGlite・実 PostgreSQL・DOM で権限、競合、再送、監査、原子性、入力保持、最新取得失敗、権限喪失と遅延応答を検証する。実サービスの認証、移行、本番運用は別途確認する。
