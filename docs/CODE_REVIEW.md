## 点検中に修正した問題

| 問題 | 修正・検証 |
|---|---|
| クリックや検索でも端末へ全状態を書き直していた | 保存対象の変更がなければ書き込みを省略。変更なしの操作で保存が発生しないことをテスト |
| 別ウィンドウの新しい保存を古い状態で上書きし得た | 保存前に保存元の内容を比較し、変更済みなら書き込みを拒否する。後から古いウィンドウで保存するケースをテスト |
| 保存失敗の表示が一時通知だけだった | 保存失敗・競合を画面に残す。保存できない場合は成功表示を取り下げる |
| 保存データの段階・期限の検証に翻訳辞書全体を使っていた | 業務用の許可値に限定。`constructor`、`toString`、無関係な翻訳キー、文字列以外の値を拒否するテスト |
| 案件配列の先頭を更新対象にしていた | 案件IDで対象を取得する。通常の保存データは引き続き復元可能 |
| 開いているダイアログの内容更新で終了処理を重複登録した | 初回に開く場合だけフォーカス復帰と終了処理を登録 |

ウィンドウ間の保存比較は、先行する変更を検知するための対策。localStorageにはDBのトランザクションと同等の原子的な比較更新がなく、完全な同時編集制御ではない。

参照監査は保守的な文字列照合で、未参照候補を検出するためのもの。全実行経路の到達可能性を証明する解析ではない。動的キーは明示的なマップに置き、検出結果を確認してから削除する。

## 残る改善点（優先順）

1. **画面操作の自動テストと実機確認**：公開前の確認に、一覧の絞り込み、記録、更新案、ダイアログ、再起動、狭幅・長文・キーボード操作を加える。現在の単体テストだけではレイアウト崩れやフォーカス移動は保証できない。
2. **本番DB・認証・組織ごとの権限・同期**：現在は公開デモと端末内保存。実顧客の業務運用には、サーバー側の権限検証、版を使った更新、バックアップ、監査記録が必要。今回のクリーンアップでは新たなDBを作成していない。
3. **画面コードの分割**：`src/prototype/app.ts` に画面・ルーティング・イベントが集中している。次のReact移行に合わせ、表示部品・案件操作・画面状態を分ける。現行の文字列テンプレートを大規模に作り直す二重作業は避ける。
4. **GitHubでの軽量な検査実行**：現在はローカルで `npm run check`。PRで型・参照・単体テストを実行し、文書のみの変更は除外、キャッシュと古い実行のキャンセルを使う。VercelのGit連携も未設定で、今回の配信はCLIから行う。
5. **アプリ更新の案内**：新しいPWAを準備できたときに案内を表示する。作業中の強制更新は避け、保存確認後に切り替える。現在は全Relay画面を閉じて開き直す方式。
