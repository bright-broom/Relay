# Relay 料金シミュレーション

2026-09-13 / 初期実装：商品導入前後の月額負担・総支払額比較

## プロダクトと操作

Relay内の一機能として管理する。営業担当者が案件を開き、左サイドバーの電卓アイコンから条件を入力する。案件詳細から開いた場合は顧客名のみを引き継ぐ。現在の案件は架空データのため、金額を案件や会話から推測して自動入力しない。

1. 導入前の月額、導入後の月額（分割払いを除く）、初期費用を入力。ゼロ円は「0円」ボタンでも明示指定できる。
2. 比較期間を選択。分割払いがある場合だけ期間を選ぶと月額欄を表示する。「分割払いなし」への切替で月額0を使い、戻すと編集中の金額を復元する。標準外の月数は「その他・直接入力」で指定できる。
3. 月額・総額・差額と内訳を確認する。条件変更で結果は再計算され、確認チェックは解除される。不正入力の間は前の結果を残さない。
4. 金額の出典（見積書・請求書・料金表・その他）と資料の日付を選び、費用の範囲を確認する。資料名・番号は任意の詳細欄、「その他」の説明は必須。出典の日付は自動入力しない。
5. 「お客様に提示」で画面全体を提案表示に切り替える。背後の案件・社内メモを隠し、金額・前提・出典を表示する。「条件を変更」で同じ入力に戻れる。

現段階の入力・出典はメモリーだけに保持する。サーバー送信、localStorage、公開URL、LINE送信、共有リンク作成は行わず、閉じると破棄する。提示モードは別権限の共有画面ではなく、営業担当者の端末で見せる表示モード。

## モジュール境界

- `src/pricing/comparison.ts`：入力検証、十進数計算、月別累積明細。UI・DOM・DB・AIに依存しない純粋関数。
- `src/pricing/profiles.ts`：業界条件の入口。現在は税込JPY・毎月一定の費用比較のみ。期間選択肢などの条件を画面から分離。
- `src/app/pricing.tsx`：入力、即時比較、出典の確認、顧客向け表示。既存ダイアログ、日英翻訳、中央トークン、既存認証境界を利用。
- `tests/pricing.mjs`：固定例、境界、500通りの独立した整数円の支払い明細との照合。

2026-09-13に画面アダプターをReact＋shadcn/uiへ交換した。計算と業界ルールは同じリポジトリ内で独立して保ち、別アプリでも利用する段階でパッケージ化する。計算エンジンの変更を伴わず、全画面のReact移行と共通部品への置換を実施した。

## 計算契約 v1

入力金額は税込・0〜9,999,999,999円の整数文字列。空欄・負数・小数・指数表記・桁区切りを拒否する。通貨はJPY限定。期間はエンジンで1〜420か月、分割払いなしは月額0かつ期間0。画面は標準期間のプルダウンと任意月数の入力を提供し、同じ範囲検証を適用する。

| 項目 | 計算 |
|---|---|
| 導入前総額 | 導入前月額 × 比較月数 |
| 導入後総額 | 初期費用 + 導入後月額 × 比較月数 + 分割月額 × min(分割期間, 比較月数) |
| 分割払い中の月額 | 導入後月額 + 分割月額 |
| 分割払い終了後の月額 | 導入後月額 |
| 総額差 | 導入前総額 − 導入後総額。負値は費用増として表示 |
| 比較期間後の残債 | 分割月額 × max(分割期間 − 比較月数, 0)。比較総額とは別に表示 |

初期費用は月0、分割払いは月1から発生する。初期費用には頭金・手数料等のその時点で払う金額を入力し、分割払いする元本を重ねて計上しない。導入後月額には分割払いを含めず、二重計上を避ける。同じ費用範囲を比較し、比較前に存在するローン等が途中で終了するケースはこの一定月額モデルの対象外。

[decimal.js公式仕様](https://mikemcl.github.io/decimal.js/)を確認し、10.6.0を固定採用。専用Decimalコンストラクターの精度は40桁。v1は整数円の加減乗算のみのため、中間・最終とも丸め処理は発生しない。結果は十進文字列で返し、画面の通貨表示にはBigIntを使用する。結果に計算バージョンと検証済み入力を含める。

補助金、売電収入、税額算出、物価上昇、設備劣化、交換費用、変動金利、借り換え、ボーナス払い、初回・最終回だけ異なる分割払いは未対応。特に金融機関の融資計算や確定見積もりとは扱わない。費用の前提と概算表示を顧客画面に残す。

## 正しさの検証と実例

架空の固定例：導入前20,000円/月、導入後8,000円/月、初期100,000円、分割5,000円/月×60回。

- 120か月比較：導入前2,400,000円、導入後1,360,000円、差1,040,000円、残債0円。
- 12か月比較：導入前240,000円、導入後256,000円。総額は16,000円増加し、別に残債240,000円が残る。

独立したBigIntの月次台帳を500通り作り、総額・差額・残債・月別累積値を照合する。分割払い終了境界、ゼロ、上限、不正値も検証する。これは上の計算契約への適合を検証するもので、入力金額や販売条件の正当性を保証するものではない。

`npm run check`に料金計算テストを追加。ブラウザーによるローカルURLへのアクセスが安全ポリシーで拒否されたため、390 / 768 / 1440pxの実表示、長文・キーボード操作、提示モードの実動作は未検証。既存レスポンシブGridとトークンを利用する。

## 次の段階

元のClaudeアーティファクトと正式な商品条件を受領後、固定例との照合を行う。単に古い計算式をコピーせず、費用・税・丸め・適用期間・出典を仕様として確定する。

業界別機能は、承認済みの条件を標準の費用明細へ変換するアダプターとして追加する。メーカーの予測値や補助金を確定金額と混同しない。価格表等を公開コードへ埋め込まず、認証されたデータとして取得する。

保存機能を追加するときは、サーバーで同じ入力検証・計算を再実行し、クライアントが送った結果を信用しない。案件へのアクセス権を確認し、入力・出典・エンジン版・業界ルール版・作成者・作成日時を変更不能の試算スナップショットとして保存する。価格表更新後も過去の提案結果を再現できるようにする。案件保存基盤が未実装の現時点では、正式保存済みと表示しない。
