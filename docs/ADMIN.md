# Google認証付き管理者ページ

入口は `/admin`。初期版では利用許可アカウント・管理者／メンバーの権限・有効なログインセッション数・Google／DB／LINE／カレンダー暗号化の設定状況を確認する。許可アカウントの追加・権限変更はサーバー環境変数で行う。画面内の追加・編集・削除機能はない。

## 認証と権限

既存のGoogle OpenID Connect（Authorization Code＋PKCE）を共通利用。Googleで確認したメールと、毎回のセッション照会に基づいて認可する。

- `ALLOWED_GOOGLE_EMAILS`：通常の利用許可リスト。
- `ADMIN_GOOGLE_EMAILS`：管理者リスト。**両方に登録されたアカウントだけ**を管理者とする。
- 管理者リストが空・未設定なら管理者は0人。通常ユーザーや最初のログイン者を自動昇格しない。
- メールはカンマ区切り、前後空白を除去し大文字小文字を区別しない。ドメイン全体の許可は行わない。
- 環境変数はサーバー専用。実アドレス・秘密情報を公開コードやクライアント設定へ書かない。

`GET /admin` は未ログインならGoogleログイン画面、一般ユーザーなら403の権限不足画面を返す。許可された管理者だけにアプリシェルを返す。通常アプリのサイドバーには全員に管理者入口を表示する。権限がない場合は鍵と破線、認証が必要な読み上げ名で制限状態を示す。入口自体は操作でき、`#admin` で管理者認証画面へ進む。権限不足・未ログイン時は管理情報を描画せず、Googleログインから `/admin` へ戻る。一般ユーザーの再ログインだけでは管理者に昇格しない。`file://` では認証案内と無効なログインボタンを表示し、外部設定のない認証動作を模擬しない。

`GET /api/admin/overview` は未認証401・一般ユーザー403。画面の表示フラグ、URLの `#admin`、ローカル保存、リクエストヘッダーから管理者権限を受け取らない。設定を外したアカウント、期限切れ・削除済みセッションは既存Cookieでも拒否する。API失敗・拒否・再取得中には、以前取得した管理情報を画面から消す。

ページとAPIは既存のprivate/no-store、CDN no-store、正規Origin制約、CSPを継承。アカウント一覧はAPI応答のみで、公開静的ファイルや端末の案件保存へ含めない。レスポンシブの共通部品・日英文言・RTLも継承する。

## Googleログインからの復帰

管理者ログイン入口は `/api/auth/start?destination=admin`。戻り先は `/` と `/admin` の2択。管理者用の固定マーカーをランダムstateへ加え、既存のDBに保存する。コールバックは保存済みstateを一度だけ消費し、OIDCライブラリによるstate／nonce／PKCE／署名等の検証後、保存した戻り先へ移動する。コールバックの任意URL指定は採用しない。

Googleに登録するリダイレクトURIは既存の `APP_ORIGIN + /api/auth/callback` のまま。`/admin` をGoogleのコールバックURIへ登録しない。要求スコープも `openid email` のまま。追加マイグレーションや別のGoogle OAuthクライアントは不要。

## 設定と利用開始

1. [Google認証・DB設定](AUTH_LINE.md)を完了する。
2. 対象Vercelプロジェクトのサーバー環境変数に、利用許可リストと管理者リストを設定する。`.env.example`に空の設定名のみを記載。
3. 対応コードをマージ・デプロイし、設定反映後に `/admin` へアクセスする。
4. 実Googleアカウントで管理者の往復、一般ユーザーの403、権限削除後の拒否を確認する。

環境変数の変更は新しいデプロイで反映される。PR作成だけでは本番コード・権限設定を変更しない。

設定状況は設定値の有無を表す。DB表示は一覧取得のSQLが成功した場合だけ返す。他の設定表示は実LINE配信や実カレンダー接続を証明しない。ログイン数は期限内のセッション数で、現在オンラインの人数・端末台数ではない。

## 検証

`npm run check` に含まれるサーバーテストは、合成署名付きGoogleプロバイダーとPGliteの実SQLで、管理者への復帰、任意戻り先拒否、未認証・一般ユーザー・偽装フラグ・未設定権限・権限失効・セッション期限・Origin制限・秘密値の非公開を確認する。Reactテストは管理情報の表示、403後のデータ消去、401のログイン導線、503の再試行表示を確認する。

これらは実Googleログイン・Vercel実DB接続・スマホ／iPad実機の表示確認ではない。既存のブラウザーアクセス制限を回避しない。認証に必要な外部設定が揃うまでは本番ログインの利用開始済みと扱わない。

公式資料：[Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)。既存の依存関係を利用し、新たな認証ライブラリは追加しない。

## セッション変更時の画面破棄

表示中の主体（Google subject・管理者権限）はウィンドウ内に保持し、共有localStorageを比較の正本にしない。既存の定期セッション確認で主体・権限の変更、期限切れ、不正な応答を検知したら、Reactルートを破棄して再認証へ移る。モーダルのポータルと管理情報も破棄し、各機能のeffect cleanupで進行中の取得を中止する。遅れて届いた応答やアプリのスクリプトが管理情報を再表示することも防ぐ。

通信失敗時にもルートを破棄し、接続復旧時はページを再読み込みして認可し直す。初回のメニュー権限は検証済みセッションから取得し、古いHTMLの表示フラグを引き継がない。これは確認時に失効を検知する動作で、サーバーからの即時失効通知ではない。表示中の定期確認は既存の60秒間隔を維持する。

`test:session`は実際のセッション起動コードを合成応答で実行し、別ウィンドウが共有ストレージを更新済みの場合、ストレージ拒否、同一ユーザーの権限変更、期限切れ、不正応答、通信復旧を確認する。Reactテストは表示済みデータの破棄、進行中の取得の中止、遅延応答と遅延起動による再表示の防止を確認する。
