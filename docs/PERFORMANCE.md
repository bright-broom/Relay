# 読み込み性能と分割方針

初回に必要な画面を eager loading、重い機能を lazy loading に分ける。2026-09-17 の変更では、初期 JavaScript の量を削減した。表示時間の短縮率を保証する値ではない。

## 読み込みの順序

| 対象 | タイミング | 意図 |
|---|---|---|
| 軽量な起動・セッション確認 | 最初 | 認証失効・本人変更を確認してからアプリを起動する |
| ナビゲーション、今日、案件一覧・詳細、更新案、取込 | 起動時に eager loading | 普段の案件操作で追加ダウンロードを待たせない |
| 料金、日程、顧客台帳、マイページ、管理 | 開いたときに lazy loading | 未使用機能のコードと計算ライブラリを初回から除く |
| 開こうとしている機能 | メニューのポインター進入・キーボードフォーカス時 | コードだけを先読みし、クリック後の待ち時間を減らす |
| 直接指定されたページ・カレンダー連携からの復帰 | セッション確認後、初期コードと並列に modulepreload | 遷移先が分かっている場合のダウンロード開始の遅れを減らす |

先読みだけでは画面をマウントせず、顧客・管理・外部連携 API を呼ばない。タブ非表示、セッション失効、オフライン、Save-Data、2G / slow-2g では操作前の先読みをしない。管理メニューの先読みは管理者だけ。接続情報 API がないブラウザーでは、操作意図に応じた先読みを行う。ページ内では同じ import の Promise を共有する。

`React.lazy` と `Suspense` は機能単位に配置する。待機・失敗中もナビゲーションとダイアログの閉じる操作を残す。閉じた後にコードが届いても、その機能はマウントしない。取得失敗時は日英の案内と再読み込み操作を表示する。再読み込みで未保存の入力が失われる可能性を案内する。

## 転送量の比較

比較対象は HTTP で「今日」を開く際の session.js と、アプリ入口から静的 import で到達する全 JavaScript。変更前は main の `20cb83f`、変更後は本変更の生成物を使用。KB は 1,000 bytes。gzip は各ファイルを Node.js 24 の `gzipSync` で個別圧縮して合計した比較値で、実際の配信圧縮形式・通信量ではない。

| 対象 | 変更前 | 変更後 | 削減 |
|---|---:|---:|---:|
| 初期 JavaScript | 1,301,621 bytes | 504,221 bytes | 約 61% |
| 同 gzip 合計 | 350,945 bytes | 約 158,229 bytes | 約 55% |
| 起動・セッション確認のみ | 108,822 bytes | 4,050 bytes | 約 96% |

初期静的 import は 10 ファイル。全依存を modulepreload で並列取得し、ファイル数増加による直列の取得待ちを抑える。直接指定された機能や操作前の先読みを含む場合、取得量は増える。CSS、HTML、API、通信遅延、サーバー起動、実機の解析・描画時間は上の表に含まない。

初期依存から Temporal、Decimal、Zod と 5 機能の画面実装が外れていることをテストする。React・共通操作部品・日英文言は初期依存に残す。

## 生成物と配信

- 正本は TypeScript。`scripts/build-modules.ts` が esbuild の ESM 分割と内容ハッシュ付きファイルを生成する。新たな手書き JavaScript は追加しない。
- `prototype/assets/module-manifest.json` が入口、静的依存、機能別依存、元ソース、サイズ、SHA-256 を記録する。圧縮サイズは実行環境差を含むため、マニフェストではなくテスト実行時に計算する。
- `src/prototype/session.ts` は成功したセッション確認後に manifest 由来の依存を先読みする。公開デモは既存の公開モードを維持する。
- `/assets/modules/…` は既存の Function を通す。名前の形式とビルドの許可リストを両方照合し、任意ファイルやパス探索を拒否する。アプリコードだけをプロセス内で共有し、API レスポンス・顧客レコードをキャッシュしない。
- アプリコードの `private, no-store`、CDN の `no-store`、CSP、API 側の本人・権限確認を維持する。`public/` に分割アプリを複製せず、Service Worker にも保存しない。
- `prototype/assets/app.js` は既存の `file://` 単体プレビュー用 IIFE として残す。通常の HTTP 起動では読み込まない。これも TypeScript からの生成物で、手書きの旧実装ではない。`prototype/` 全体は Git 管理せず、デプロイとローカルプレビューの前に生成する。
- 新しいビルドは古い分割ファイルを削除する。デプロイをまたいだ古いタブで未取得の機能が失敗した場合は、再読み込みで現行の入口・ハッシュに揃える。

## 回帰防止と検証範囲

`npm run check` に次を含める。

- 初期コードの上限：非圧縮 600,000 bytes、gzip 合計 180,000 bytes、起動スクリプト 8,000 bytes。増加時は原因と利用者への影響をレビューし、通過目的で上限を広げない。
- manifest の依存グラフ・ファイル数・サイズ・ハッシュと生成物の一致。孤立チャンク・古い出力も拒否する。
- 意図的な先読み、重複抑止、通信・セッション条件、未マウントの保証。
- 読み込み中に閉じる、失敗表示、別の画面への復帰、既存の入力保持・キーボード・認証失効・API 権限。
- 全チャンクの配信、未知の名前・パス探索・不正メソッド・設定済みの異なる origin の拒否。

今回の実ブラウザー検証は、内蔵ブラウザーと Chrome の検証ツール接続がともにタイムアウトした。390 / 768 / 1440 px の新たな目視確認、実回線での LCP / INP、iOS / Android 実機は未検証。DOM テストや転送量を実機の表示時間として扱わない。

次の測定対象は、実ブラウザーの初回・再訪・直接遷移・最初の料金表示と、認証後の顧客検索 API の待ち時間。必要な機能を実行する条件を揃えてから、サーバー起動・通信・JavaScript・描画のどこが支配的かを判断する。認証の省略や機密データの永続キャッシュで高速化しない。

変更の取り消しは、この変更のソース・配信設定・生成物を一緒に戻して再ビルドする。DB マイグレーションや保存形式の変更はない。
